Support & feedback

Contact PDFora

For product support, privacy questions, bug reports, or general feedback, email hikmatmarwat1100@gmail.com.

Email hikmatmarwat1100@gmail.com

Getting product support

Tell us which PDFora tool you were using, what you expected to happen, and the error message or behavior you saw. Browser and device information can also help diagnose interface problems.

For your privacy, do not email confidential documents, passwords, financial records, identity documents, medical files, or other sensitive PDF content unless it is truly necessary for your request.

Privacy or deletion requests

If you previously sent personal information directly to hikmatmarwat1100@gmail.com and want to ask about that support correspondence, identify the relevant message so the request can be reviewed. Files selected in the PDF tools are processed locally in your browser and are not attached to a user account or sent to a PDFora document library.

Feedback and corrections

You can use the same email address to report a broken page, inaccessible control, inaccurate help text, or a document type that produces an unexpected result. Clear reproduction steps are more useful than sending the document itself whenever possible.

Response expectations

Support availability and response times can vary. PDFora is not an emergency or time-critical service, so keep local copies of important documents and do not depend on a support response for an urgent submission deadline.

How to send a useful support message

A short description is often enough for a general question, but technical problems are easier to understand when the report includes context. Tell us which PDFora tool you used, what you expected to happen, what actually happened, and whether the problem appeared before processing, during processing, or after opening the exported file. If an error message appeared, copy the exact wording when possible.

For browser-related issues, it can help to include the browser name, operating system, device type, approximate file size, and page count. You do not need to include the document itself to make a first report. In many cases, the behavior can be investigated from the workflow and file characteristics alone.

Please protect sensitive documents

PDFora is designed so supported document operations can run in the browser, but email support is a separate communication channel. Do not attach passports, financial statements, medical records, contracts, identity documents, private customer data, passwords, or other confidential files to an email unless there is a clear and appropriate reason to do so. A description of the issue is usually the best first step.

If a problem only occurs with one sensitive file, consider whether you can reproduce it with a non-confidential sample that has similar page dimensions, fonts, image density, or encryption settings. This helps protect your information while still providing useful technical detail.

What we can help with

  • Questions about how a PDFora tool is intended to work.
  • Unexpected browser errors or export problems.
  • Broken links, missing assets, navigation issues, or unclear instructions.
  • Privacy-policy or cookie-policy questions about the website.
  • Accessibility feedback, including keyboard or screen-reader difficulties.
  • Corrections to documentation where a limitation or workflow is described inaccurately.

Support cannot guarantee that every third-party PDF, Office file, scan, font, signature, or encryption configuration will convert perfectly. Document formats are complex, and some files need desktop software or a specialist workflow. When a limitation is known, the goal is to explain it clearly rather than promise a result the browser cannot reliably produce.

Responsible and authorized use

Please use the tools only with documents you own or are authorized to process. For example, the Unlock PDF workflow is intended for a protected file when you know the current password and have the right to create an unlocked copy. It does not recover unknown passwords or provide access without the current password. Similarly, visual whiteout in an editor should not be treated as permanent legal redaction.

If your organization has formal requirements for records retention, legal signatures, accessibility, encryption, privacy, or regulatory compliance, follow those requirements rather than relying only on a general-purpose browser utility.

Response expectations

Messages are reviewed as availability allows, so response time can vary. Sending repeated copies of the same message does not normally make a technical issue easier to investigate. One clear report with the relevant details is more useful. If the problem changes after you update your browser, reduce the file size, or try a different document, reply with the new information so the report stays in one thread.

Before contacting support, you may also find an answer in the FAQ or the PDF Guides. Those pages cover common questions about local processing, conversions, image quality, browser memory, passwords, scanned files, and document organization.
